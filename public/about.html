What this is & isn't

A data layer, not a study

And, just as importantly, what it does not. This is a data-engineering project, not a human-wildlife conflict study. It assembles open biodiversity data into a clean, documented, queryable map — a basic input that specialists in the field could draw on, not an analysis that stands in for their work.

What this actually is

Human-wildlife conflict analysis is a serious specialist discipline. Done properly it draws on incident records, population modelling, compensation data, and long community consultation, and getting it wrong has real consequences — misdirected funding, misplaced blame on communities, animals killed on weak evidence. This project does not attempt that, and does not claim to.

What it is: a demonstration of data engineering. It takes scattered open datasets — species occurrences, population density, protected-area and national boundaries — and turns them into one coherent, honestly-labelled, verifiable layer that runs on low-cost regional hosting. The value on offer is the plumbing done well, with its limits stated plainly, not any ecological finding. Think of it as a tidy first input a specialist might place alongside the data that actually matters, not a substitute for it.

Context, not a mandate

There is real funded work in this landscape — the IUCN–Total LandCare Human-Wildlife Co-habitation Project for the Malawi–Zambia TFCA, backed by Germany's BMZ through KfW. It exists because conflict here is real and documented. That work is the reason a data layer for this area is worth building at all. This project is not part of it, not commissioned by it, and does not speak for it — it simply uses the same open data the field relies on. The project's launch brief →

What the engineering delivers
  • Pulls live species occurrences from GBIF into a clean, cached layer
  • Overlays population density, protected areas, and national borders — all open, redistributable data
  • Flags each record's context (inside a park, in settled areas) as queryable attributes
  • Keeps a documented history table so the data can be read over time
  • Runs on low-cost shared hosting anyone in the region can afford
What it is NOT
  • A human-wildlife conflict study — that is specialist work with real stakes
  • A hotspot or risk model — presence is an input to those, not the result
  • A source of incident data — those records sit with DNPW and partners
  • A census — a dot is a record, often not even one animal
  • A substitute for fieldwork, local knowledge, or expert judgement

What a dot means

Each point on the map is a record, not an animal and not a count. Behind each one is a set of facts that decide what it means: how many individuals (often unstated — a single record can be a lone animal or a herd of forty), what kind of record (a live sighting, a museum specimen, a camera-trap trigger), how it was recorded, by whom, and how precisely its location is known. Reading these fields honestly is the difference between a map that informs and one that misleads — which is exactly the kind of care a specialist needs from any data handed to them.

So blank space on the map means "no record here", never "no animals here". Density reflects where people looked and reported, not true abundance. These are ordinary limits of open occurrence data, stated plainly so the layer can be trusted for what it is.

Put plainly: this is well-engineered, honestly-caveated open-data plumbing for a landscape where the real work is done by others. It is offered as a clean input to that work, not as a finding of its own.
